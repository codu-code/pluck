How MCP auth actually works

By Ciara Walsh

The short version is simple. The client never hands the server a password. It gets a token, scoped to what the user agreed to, and sends it with each call.

The scope is the contract. If a tool can delete, the scope should say so, and the user should see it before they agree.

Refresh is where most servers go wrong. A long-lived token in a config file is a password with extra steps.
