# Languages

Pluck speaks English, Spanish, Portuguese (Brazil), French, German, Japanese, Italian, Dutch, Korean and Chinese (Simplified). English is the source. Every other language falls back to English key by key, so an untranslated string shows in English, never as a key.

## Where the words live

`packages/i18n/messages/<catalog>/<locale>.json`, one file per catalog and language:

| Catalog | Used by | Read with |
|---|---|---|
| `site` | the marketing pages | `useTranslations("site")` / `getTranslations("site")` (next-intl) |
| `app` | the signed-in web app and sign-in | `useTranslations("app")` (next-intl) |
| `email` | every email the server sends | `createTranslator` in `apps/web/lib/emails.ts` |
| `ios` | the iPhone app | `useTranslations("ios")` (use-intl) |
| `extension` | the Chrome extension's popup and options; its `manifest` section is the store name, description and shortcuts | `useTranslations("extension")` (use-intl); the manifest through `public/_locales` |
| `share` | the iPhone share sheet (Swift) | `String(localized: "key")` / `Text("key")`, through `targets/share/Localizable.xcstrings` |

Messages are ICU (`{count, plural, one {# Item} other {# Items}}`). Keys are typed from English: a key that does not exist fails `pnpm typecheck`.

The share catalog is flat and has no plurals, because Swift reads it as an Apple String Catalog; `{name}` becomes `%1$@`. The Chrome `_locales` and the String Catalog are generated: after changing the `extension` or `share` catalogs, run `node scripts/i18n-sync.mjs`. `pnpm test` fails until you do.

## Which language

- **Web:** the language picked in the site footer or Settings (the `pluck_locale` cookie), else the browser's (`Accept-Language`). `apps/web/i18n/request.ts`.
- **Account:** `settings.locale`, set at sign-up from the browser and by the Settings picker. Emails go out in it. The sign-in email uses the request's language, since there may be no account yet.
- **iPhone:** the phone's language, or the one picked for Pluck in iOS Settings (Pluck lists its languages in `CFBundleLocalizations`, so iOS offers the choice). Settings, Language opens it. Hermes has no `Intl.PluralRules`, so `apps/ios/lib/plurals.ts` adds it, with the rules for each language; without it every plural message shows its key.
- **Chrome extension:** the browser's language.
- **Offline:** the iPhone app, the share sheet and the extension carry every catalog in their bundle, so nothing is fetched to show a language and it works with no connection. On the web, the service worker (`apps/web/public/sw.js`) keeps the offline page in the language the app is shown in; the app tells it on every load, and when the language changes (Settings, the site footer) the page is kept again in the new one.

Portuguese of any region reads Brazilian Portuguese. Chinese reads Simplified only; Traditional (zh-TW, zh-HK) falls through to the next preferred language, then English.

## Adding or changing a string

1. Add the English message to the right catalog in `packages/i18n/messages/<catalog>/en.json`.
2. Use the key in code.
3. Leave the other languages: they show English until translated. Never put a key in another language that English does not have (the test fails).
4. For `extension` or `share`, run `node scripts/i18n-sync.mjs`.

## Translating

- Each language has a glossary in `docs/i18n/<locale>.md`: how Pluck's product words (Pluck, Plucked, Item, the seven Kinds, Inbox, Later, Archived, Done, Tag, List) are said, and why, from how comparable apps in that market say them.
- The tone rules hold in every language: no exclamation marks, no emoji, "your AI" and never one vendor alone, expiry copy says the Item moves to the Archive and nothing is deleted.
- "Pluck" stays in Latin letters as the brand everywhere.
- Every placeholder in English appears in the translation, and only those (the test checks).
- When a language is fully translated and verified, add it to `COMPLETE` in `packages/i18n/src/i18n.test.ts`. From then on, a missing key fails the test instead of falling back to English.
- German runs about 30% longer than English: check buttons, tabs and titles at phone width. Japanese, Korean and Chinese fall back to the system fonts (the brand fonts have no CJK glyphs): `apps/web/app/globals.css` names each language's system font after the brand fonts, by the page's `lang`. `e2e/languages.spec.ts` checks German and Japanese for sideways scroll at phone width.
