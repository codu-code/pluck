Rotating refresh tokens

Step 1

Authorisation in a connector is about who the server is acting for. The token carries the person, the scopes carry what they agreed to, and the audience check makes sure a token minted for one service cannot be spent at another.

pnpm install
pnpm test

Step 2

Refresh tokens should rotate. Each use returns a new one and retires the old, so a stolen token works at most once before the real client notices that its next refresh has failed.

Step 3

Rate limits protect the people who use a free service from the few who abuse it. Generous limits for a person, tighter ones for an address, and an honest message with a retry time when either is reached.

pnpm test

Step 4

The release checklist fits on one card. Tests green, migration reviewed, rollback written down, and one person who is awake for the next hour and knows they are on call for it.
